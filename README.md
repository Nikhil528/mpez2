# MPEB License System

## What it includes

- Render Web Service
- PostgreSQL-backed license database
- Admin panel at `/admin`
- Random license key generator
- One-device binding
- Device reset
- Enable/disable license
- Optional expiry date
- Existing MPEB receipt printing logic
- Bookmarklet-friendly `/receipt.js`

## Render deployment

1. Push this repository to GitHub.
2. In Render choose **New > Blueprint** and select the repository containing `render.yaml`, OR create the Web Service and Postgres manually.
3. If using the Blueprint, set these secret environment variables for the web service:
   - `ADMIN_USER`
   - `ADMIN_PASSWORD`
4. `LICENSE_SECRET` is generated by Render.
5. The free Postgres database is suitable for testing but Render currently states that free Postgres databases expire after 30 days. Upgrade the database or move the license database to another persistent provider for long-term production use.

## Admin

Open:

https://YOUR-SERVICE.onrender.com/admin

The browser will show an HTTP Basic Auth prompt. Use `ADMIN_USER` and `ADMIN_PASSWORD`.

## License activation

The bookmarklet loads:

https://YOUR-SERVICE.onrender.com/receipt.js

The first run asks for a license key. The server binds that key to a random installation ID stored in the browser's localStorage.

## Important security limitation

A browser bookmarklet cannot prove a physical Windows machine identity with 100% certainty. This implementation provides server-side one-install/browser binding and rejects the same key from a different installation ID. A determined user who can modify the bookmarklet/browser storage can bypass client-side controls. For stronger hardware-level enforcement, bind licenses to a Windows desktop agent that reports a server-generated machine identifier.

## Existing receipt fields

The receipt script reads:

- `rcptConsumerId`
- `rcptConsumerName`
- `rcptTxnId`
- `rcptTime`
- `rcptBillMonth`
- `rcptTotalPaid`

and searches `<strong>` elements for the K2024 reference number.
